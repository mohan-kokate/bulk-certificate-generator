# Bulk Certificate Generator

A Python REST API that accepts a list of recipients, validates their data, generates one PDF certificate per recipient from a single predefined template, tracks each result, and provides download endpoints.

## Technology

- Python 3.10+
- FastAPI
- SQLite relational database
- ReportLab for PDF generation
- Pytest and FastAPI TestClient

## Design decisions

- **Bulk endpoint:** One `POST /jobs` request accepts up to 500 recipients.
- **Relational persistence:** SQLite stores jobs and per-recipient results. Foreign-key enforcement is enabled.
- **Failure isolation:** Each certificate is generated in its own `try/except`; a single failure is recorded without stopping later recipients.
- **Processing model:** Generation is synchronous for this assignment. The API returns after processing the submitted batch. This keeps deployment simple and makes status immediately inspectable. For very large production workloads, move processing to a background queue (for example Celery/RQ) and return immediately after creating the job.
- **Validation:** Pydantic validates required fields, string lengths, recipient count, and email format.
- **Template:** A single landscape A4 PDF design is used. No template editor is included.

## Setup

Create and activate a virtual environment.

### Windows (PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Run the API

From the project root:

```bash
uvicorn app.main:app --reload
```

Open interactive API documentation at http://127.0.0.1:8000/docs.

The SQLite database (`certificates.db`) and generated PDF files (`generated/`) are created automatically. Optional environment variables:

- `DATABASE_PATH`: database file path
- `CERTIFICATE_DIR`: output directory for generated certificates

## API usage

### 1. Create a bulk generation job

`POST /jobs`

Example request:

```json
{
  "event_name": "Python Bootcamp 2026",
  "certificate_title": "Certificate of Completion",
  "recipients": [
    {"name": "Asha Patil", "email": "asha@example.com"},
    {"name": "Rahul Shah", "email": "rahul@example.com"}
  ]
}
```

Example response:

```json
{
  "job_id": "generated-uuid",
  "status": "completed",
  "total": 2,
  "succeeded": 2,
  "failed": 0,
  "status_url": "/jobs/generated-uuid"
}
```

The actual `job_id` will be a UUID generated by the API. Submit a real request to get the actual response.

### 2. Check job status and results

`GET /jobs/{job_id}`

Returns totals and one result per recipient, including status, download URL for successful certificates, and an error for failed certificates.

### 3. Download a certificate

`GET /certificates/{certificate_id}`

Returns the generated PDF as a file download. The certificate ID is available in the job results.

### Other endpoints

- `GET /health` — health check
- `GET /` — API overview

Invalid request data returns HTTP `422`. Unknown jobs and unavailable certificate files return HTTP `404`.

## Known scope and production considerations

This is an assignment-sized implementation. Processing is synchronous, SQLite is suitable for local evaluation, and generated PDFs are stored on the local filesystem. For production, consider a durable background queue, PostgreSQL, object storage, authentication/authorization, rate limits, cleanup policies, and monitoring. Do not expose this API publicly without appropriate access controls.
